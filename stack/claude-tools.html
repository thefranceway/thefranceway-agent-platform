Agent Architecture · How it all connects

Your full agent stack — visualized

Every agent, tool, and proxy in one diagram. Two distinct patterns co-exist in your stack: sub-agents (Claude Code tasks that spawn, work alone, and return) and an agent team (your platform's 15 agents with shared memory). MetaClaw wraps the platform side, injecting skills into every LLM call transparently. View live Brain Graph ↗ — longmem eval: 94.7% (episodic memory + cross-KB routing + recency weighting).

Sub-Agents — Contractors
Spawn → work alone → return → done
Their own context window. Parallel execution. No shared state. Best for independent, isolated tasks you want to run simultaneously without cluttering the main context.
Task → Explore · Plan · General Purpose · Claude Code Guide
Agent Team — Employees
Always running · shared state · collaborate
Long-running processes. A lead agent, working agents, and shared task state. They can share updates and respond to each other in real time. Best for tasks that require collaboration.

MetaClaw — Skills-Only Proxy

port 30000 · 44 skills loaded · launchd: com.metaclaw.proxy

Transparent proxy that sits between your agents and the Anthropic API. Every LLM call passes through it — MetaClaw finds the most relevant skills from your library, injects them into the system prompt, then forwards to Anthropic. You don't call it directly. It just works.

How to add a skill

1. Create a directory: mkdir ~/.metaclaw/skills/my-skill-name/
2. Add a SKILL.md file with this format:
---
name: my-skill-name
description: One line — when should this skill be injected?
category: platform|content|crypto|research
---

# Your skill content here
(context, commands, patterns agents should know)

3. No restart needed — skills are re-read on every request.
When to add one: any time you find agents needing context you keep repeating — new token, new deploy target, updated brand rules, new platform pattern.
